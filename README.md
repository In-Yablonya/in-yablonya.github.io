# Яблоня — сайт игровой студии

Официальный сайт нашего проекта «Яблоня» (Yablonya). Чистые HTML, CSS и JavaScript без сборки: GitHub Pages отдаёт файлы как есть.
Игры в этом репозитории не хранятся: файлы лежат в **Releases** репозиториев игр, а сайт даёт на них прямые ссылки.

## Что где лежит

| Файл | Что это |
|---|---|
| `index.html` | Главное меню (тёмно-синий фон), кнопки «Аккаунт» и «Обратиться в поддержку» |
| `projects.html`, `js/projects.js` | Раздел «Проекты»: плитки игр, окно со скриншотами и кнопками. Описания игр — вверху `js/projects.js` |
| `js/links.js` | **Ссылки на игры** (скачивание и браузерные версии): единственный файл, который правится при выходе новой версии |
| `.claude/check-links.js`, `.claude/serve.js` | Проверка всех ссылок командой `node .claude/check-links.js` и локальный сервер для просмотра сайта |
| `team.html`, `js/team.js` | «О команде»: карточки участников (фото, имя, пара слов) и окно с подробным описанием. Участники и почта студии — вверху `js/team.js`; фото лежат в `img/team/`, заглушка для тех, кто не согласился, — `img/team/placeholder.jpg` |
| `news.html`, `js/news.js` | «Новости Яблони»: новости администраторов, лайки/дизлайки, комментарии и ответы на них |
| `news-editor.html`, `js/news-editor.js` | Страница администратора: написать, поправить и удалить новости (кнопка «+» на странице новостей) |
| `moss-empire.html`, `js/moss.js` | «Империя Мха»: фото, описание и посты о ходе проекта (их пишут администраторы) |
| `js/chat.js` | Поддержка: чат игрока с администраторами и диалог «Ответить на вопросы» для администраторов |
| `js/firebase-config.js` | Описание Firebase-проекта (`firebaseConfig`) |
| `js/backend.js`, `js/account.js` | Анонимный вход, ID игрока, никнейм, чаты; окно «Аккаунт» |
| `database.rules.json` | Правила доступа Realtime Database — их нужно опубликовать в Firebase |
| `js/i18n.js`, `js/init.js`, `js/main.js`, `css/style.css` | Тексты ru/en, тема и язык, общие стили |
| `js/fx.js` | Анимации при нажатии на кнопки и карточки: случайный эффект из списка |
| `texturs/` | Есть только на компьютере автора, в GitHub не попадает (см. `.gitignore`): туда кладут исходные картинки, а на сайт они попадают уже готовыми файлами из `img/`. Чтобы заменить картинку плитки главного меню, положите новый файл в `img/menu/` с тем же именем (лучше 16:9, от 960×540) |

Язык определяется по языку браузера (русский или английский), тема — по системной; переключатели сохраняют выбор в браузере.

## Анимации

- **При нажатии** на кнопки и карточки запускается случайный эффект: конфетти, искры, круги, яблоки (фирменный), штрихи-салют, пузыри, волна, «желе», покачивание, свечение. Эффекты берутся «колодой»: пока не показаны все десять, ни один не повторяется. Список и код эффектов — в `js/fx.js` (массив `EFFECTS`): ненужный эффект можно удалить, свой — написать и добавить.
- Отключить эффекты у конкретной кнопки: `data-fx="none"`. Закрепить за кнопкой один эффект: `data-fx="confetti"`.
- **Плавные появления, наведения и окна** описаны в конце `css/style.css` (раздел «анимации»). Логотип в меню медленно вращается, заголовок переливается цветами логотипа, карточки приподнимаются при наведении, новые сообщения чата «выскакивают».
- **Для тех, у кого в системе включено «уменьшить движение»**, все эффекты и появления отключаются сами. Появления также включаются только после того, как браузер нарисовал первый кадр (флаг `anim-on` из `js/init.js`), поэтому страница не может остаться «невидимой».

## Посмотреть сайт у себя

Открывать `index.html` двойным щелчком не стоит: аккаунты и поддержка (Firebase) работают только по адресу `http://` или `https://`, а у файла адрес `file://` — окно «Аккаунт» покажет «Сайт открыт как обычный файл». В папке сайта лежит готовый маленький сервер (нужен установленный Node.js):

```bash
node .claude/serve.js
```

Он напишет адрес `http://localhost:8080`. Или запустите любой другой локальный сервер, например:

```bash
python -m http.server 8080
```

и откройте http://localhost:8080.

## Обновить игру (ссылки лежат в `js/links.js`)

Все ссылки на игры (скачивание и «Играть в браузере») собраны в одном файле — **`js/links.js`**. Больше ничего править не нужно, и всё делается без программиста за 5 минут:

1. Выложите новый релиз в репозитории игры.
2. На странице релиза: правая кнопка по файлу → «Копировать адрес ссылки». Ссылка выглядит так:
   `https://github.com/<аккаунт>/<репозиторий>/releases/download/<тег релиза>/<файл>`
3. Откройте `js/links.js`, найдите игру и систему и замените адрес между кавычками. Запятые и кавычки не трогайте.
4. Проверьте ссылки одной командой в папке сайта:

   ```bash
   node .claude/check-links.js
   ```

   Он пройдёт по всем ссылкам и покажет ✓ (работает) или ✗ (не работает или написана неверно). Заодно проверит, что у каждой игры есть запись.
5. Обновите страницу «Проекты» (Ctrl+F5), нажмите кнопку и убедитесь, что файл скачивается. Затем отправьте изменения на сайт.

Правила: `windows`, `linux`, `macos`, `android` — файлы, `web` — игра в браузере. Нет сборки под систему — удалите строку, кнопки не будет. Пустая строка `''` показывает неактивную кнопку «скоро». Если у релиза поменялся тег или имя файла, старая ссылка перестаёт работать: копируйте ссылку заново. Если после правки страница «Проекты» стала пустой, обычно потерялась запятая или кавычка: проверьте файл командой `node --check js/links.js`.

Новая игра: название, описание и картинки добавляются в `js/projects.js` (с новым `id`), а её ссылки — в `js/links.js` под тем же `id`.

Иконка игры и скриншоты лежат в `img/games/<игра>/` как `icon.jpg` и `screen-1.jpg`, `screen-2.jpg`… (скриншоты до 1280 px по ширине, JPEG). Если файла нет, показывается заглушка. Чтобы добавить игру, положите в `texturs/<игра>/` иконку (имя файла заканчивается на `I`) и скриншоты (на `S`), а описание напишите в `js/projects.js`.

## Подключить Firebase (поддержка и аккаунт)

Если в `js/firebase-config.js` стоят `"..."`, сайт работает, но поддержка и аккаунт отключены и честно пишут об этом.

1. Ключи уже вписаны в `js/firebase-config.js` (проект `rbg228`, веб-приложение «Yablonya»). Если понадобится обновить: консоль Firebase → «Настройки проекта» → «Ваши приложения» → «Конфигурация SDK».
2. **Authentication → «Начать» (Get started) → Sign-in method → Anonymous → включить → Сохранить.** Без этого ID не выдаётся (ошибка `auth/configuration-not-found`).
3. Правила базы опубликованы. Чтобы обновить их после правки `database.rules.json`, выполните в папке сайта (нужен установленный Firebase CLI и вход в аккаунт, владеющий проектом):

   ```bash
   firebase deploy --only database
   ```

   Без CLI то же делается вручную: Realtime Database → «Правила» → вставить содержимое файла → «Опубликовать».
4. **Один раз, после публикации на GitHub Pages:** Authentication → Settings (Настройки) → Authorized domains (Авторизованные домены) → «Добавить домен» → `in-yablonya.github.io`. Без этого на опубликованном сайте не выдаётся ID (ошибка `auth/unauthorized-domain`), хотя на `localhost` всё работает.
5. Рекомендуется: в Google Cloud Console → «Учётные данные» ограничить ключ API по HTTP-источникам: `https://in-yablonya.github.io/*` и `http://localhost:*` (для проверки у себя).
6. **Администраторы** (сотрудники поддержки и владелец сайта) отмечаются вручную в базе. В консоли Firebase: Realtime Database → «Данные» → `players` → нужный игрок → поле **`admin`** → значение `true` (тип boolean). `false` или отсутствие поля — обычный игрок. У администратора вместо кнопки «Обратиться в поддержку» появляется «Ответить на вопросы» с чатами игроков. Сняли флаг — права пропадают сразу.

   Как найти нужного игрока, не спрашивая его ID (ID — это пароль): попросите человека задать в «Аккаунте» никнейм и найдите запись с этим `nickname` в `players`. У новых игроков поле `admin: false` создаётся само. У тех, кто зарегистрировался раньше, поля может не быть: добавьте его вручную.

### Как это устроено

- ID игрока — анонимный uid от Firebase. Он выдаётся автоматически при первом заходе на любую страницу сайта и лежит в cookie `yablonya_id` (резервно в `localStorage`); регистрация не нужна. У вернувшегося игрока cookie уже есть, и Firebase подключается только когда нужен (аккаунт, поддержка).
- Имя по умолчанию — «Пользователь N» (N — порядковый номер из счётчика `meta/userCounter`; в английской версии «User N»). В «Аккаунте» его можно заменить своим никнеймом (до 24 символов); пустое поле возвращает имя по умолчанию. Никнейм показывается администраторам в списке чатов и в подписи сообщений.
- ID работает как пароль: он длинный и случайный, нигде не показывается публично (в «Аккаунте» скрыт, пока не нажмёшь «Показать»), список ID прочитать нельзя. ID администратора особенно важен: по нему можно получить права, поэтому его нельзя пересылать.
- Чтобы перенести аккаунт на другое устройство (или вернуть после очистки cookie), игрок вводит свой ID в «Аккаунте» → «Войти по ID»: текущий вход привязывается к нему записью `links/<ID>/<uid>`, и браузер получает тот же никнейм и чат с поддержкой. Права проверяют правила базы, а не код страницы.

- Посты про «Империю Мха»: читают все посетители, а писать, править и удалять их могут только администраторы (поле `admin` у аккаунта). Администратор открывает страницу «Империя Мха», нажимает «Написать пост», вводит заголовок и текст (абзацы разделяются пустой строкой). У каждого поста есть кнопки «Изменить» и «Удалить». Автор подписывается своим никнеймом. Посты лежат в `mossPosts/<id>`.

- **Новости Яблони** (плитка на главной под «О команде»). Читают все. Лайки, дизлайки и комментарии доступны любому посетителю (аккаунт у него уже есть): повторное нажатие на лайк снимает его, на комментарий можно ответить, ответ на ответ крепится к главному комментарию. Новости пишет администратор: когда он заходит в «Новости Яблони», в правом верхнем углу слева от кнопки «Аккаунт» у него появляется кнопка «+» (квадрат с плюсом), она открывает `news-editor.html`. В главном меню этой кнопки нет. На странице новостей у администратора тот же вид, что и у игроков, плюс кнопка «Удалить» у комментариев для модерации. Удаление новости убирает и её комментарии с реакциями.
- Лайки хранятся под ключом-хэшем ID игрока, а не под самим ID (ID работает как пароль и в открытых данных светиться не должен). Это защищает ID, но не делает голосование неподделываемым: аккаунты бесплатные, так что накрутить лайки теоретически можно.

Структура базы чуть отличается от первоначального наброска ради безопасности:

```
meta/userCounter                  сколько номеров выдано (растёт на 1, чтобы получилось «Пользователь N»)
players/<id>                      createdAt, number, nickname (необязательно), admin, lang, theme
links/<id>/<uid>: true            какие входы Firebase «знают» этот ID
chats/<id>/<messageId>            role ('user' или 'admin'), name, text, createdAt — один сплошной чат игрока с администраторами
chatList/<id>                     сводка чата для списка у администраторов: nick, lastText, lastAt, lastRole
supportSessions/<uid>: <id>       входы, подтвердившие права администратора (создаются сайтом по флагу admin)
mossPosts/<id>                    title, text, author, createdAt, updatedAt — посты про «Империю Мха» (читают все, пишут администраторы)
news/<id>                         title, text, author, createdAt, updatedAt — «Новости Яблони» (читают все, пишут администраторы)
newsComments/<news>/<id>          text, name, role ('user'|'admin'), createdAt, parent и replyTo (для ответов)
newsReactions/<news>/<ключ>       'like' или 'dislike'; ключ — хэш ID игрока
```

`players/<id>/admin` (true/false) меняете только вы: игрок записать его себе не может, это проверяют правила базы.

Чат у каждого игрока один: писать в него могут сам игрок и любой администратор, читать — только они. Игроки друг друга не видят. Сообщения нельзя изменить или удалить с сайта; удалить можно вручную в консоли.
Ограничений на частоту сообщений в правилах нет (только длина текста). Если появится спам, подключите Firebase App Check.

## Опубликовать на GitHub Pages

Сайт лежит в публичном репозитории [In-Yablonya/in-yablonya.github.io](https://github.com/In-Yablonya/in-yablonya.github.io) организации `In-Yablonya` и открывается по адресу **https://in-yablonya.github.io/** (Settings → Pages → Source: ветка `main`, папка `/ (root)`). Имя репозитория обязано быть `<организация>.github.io`: тогда сайт открывается без добавки в адресе. Изменения, отправленные в `main`, появляются на сайте через минуту-две.

Игры — отдельные **публичные** репозитории; файлы лежат в Releases (до 2 ГБ на файл).

Версии сайта отмечены релизами на странице [Releases](https://github.com/In-Yablonya/in-yablonya.github.io/releases): первая — **v1.0.0**.

Файлы `.exe` без подписи вызывают предупреждение SmartScreen, а для `.apk` нужно разрешить установку из неизвестных источников — подсказки об этом уже есть в окне игры.
